What you get

What it does for you.

It looks after the notebook Claude Code keeps for each project and adds a journal of everything you did. It helps most when you return to a project over days or weeks.

A journal you can ask

Every exchange is kept in full, up to a size limit, one file per day. Ask about earlier work and Claude searches the journal and your notes, then tells you when it happened. The journal is not loaded into the conversation. It is searched only when you ask, by words, not meaning. Type /project-memory:memory page to read it as one page in your browser, a week at a time, with a search box. The page is a file on your computer and loads nothing from the internet.

Picks up where you left off

After every reply it notes where you stopped, and the next conversation starts from there.

Keeps old versions of notes (needs Git)

Every version of a note is kept on your computer. Ask, and an old one comes back. Each change names the conversation and what you asked that caused it.

How it works

You work. It keeps track.

Nothing to learn, nothing to run. It works on its own after every reply.

  1. Claude replies

    You work with Claude Code as you always do.

  2. The journal grows

    The exchange is saved, one file per day.

    journal/2026-11-01.md

  3. Where you stopped

    The last exchanges are kept for next time.

    handoff.md

  4. The next conversation

    Claude starts with a short briefing on where you stopped, about 900 tokens.

When a long conversation fills up

Claude can only see so much at once: your messages, its replies and the files it reads. When that fills up, Claude Code replaces the conversation with a summary, and details of a task in progress can get lost.

1Beforegetting full

Claude saves its notes.

2Duringnearly full

Claude Code is asked to let the step finish. With no room to wait, the step is written down.

3Aftersummary

Claude is told what you asked, what it last said, tasks still running and files it edited.

Your privacy

Stays on your computer.

It makes no connections of its own. What it saves stays in Claude Code's own folder, in your home folder. This page loads nothing from anywhere else, either.

Your computer
~/.claude/projects/your-project/memory
journal/2026-11-01.md
handoff.md
MEMORY.md and your notes
project-memory sends nothing out

  • No servers of its own

    It needs no account or API key.

  • Keep text out

    Put it in <private> and </private>. Claude's reply to it stays out too.

  • Forget on request

    Ask Claude to forget something. It lists the journal entries and removes the ones you confirm.

Anthropic still sees your conversation, as with Claude Code's own memory, and Claude Code keeps its own transcripts, which “forget” does not touch. The tags keep text out of project-memory's files only.

Read the privacy policy

Keys and passwords are not saved.

Sooner or later you paste a key or type a password in chat. Before anything goes into the journal, the handoff or the note kept for after a summary, project-memory replaces it with [redacted].

What it removes, and what it misses
What you typed or ran What is saved

  • A key in a command

    You typed: export API_KEY=ghp_8fK…

    Saved as: export API_KEY=[redacted]

  • A password typed in chat

    You typed: the password is plum-42…

    Saved as: the password is [redacted]

  • A cookie

    You typed: Cookie: sessionid=a1b2c3…

    Saved as: Cookie: [redacted]

  • Keys from many services
  • Passwords typed in chat, in many languages
  • Database and command-line passwords
  • Cookies and session ids
  • Look-alike spellings

  • A note that holds a secret stays out of the snapshots, and startup names it. Promoting it to the shared store is refused.

  • On Linux and macOS, the files it writes can be read only by you.

  • No tool catches every secret. A look-alike Cyrillic or Greek letter gets through, for one. Put the rest in <private>.

Anything saved before a newer version (notes, journal, handoff, snapshots) can be re-checked with /project-memory:memory rescan. It counts first and changes nothing unless you add --apply --yes. It then makes a backup that still holds the old text.

Tested before every release

About 2,500 checks run on Windows, macOS and Linux with every change, all passing. The code is scanned for problems every week, and each release gets one review. Every step has a time limit of 5 to 120 seconds, so a stuck step can't hold Claude up.

What it doesn't do

  • It searches by words, not by meaning.
  • It works in Claude Code only.
  • It doesn't sync between computers or teammates.

Install

Ready in a minute.

Not sure what you have? Ask Claude: “Do I have Node.js 22 or newer, and Git?”

  1. In Claude Code, type these 2 lines. When the second opens a menu, pick the option that installs it for you in every project (it may say user scope).

    /plugin marketplace add zdraveski/project-memory
/plugin install project-memory@project-memory

  2. Close Claude Code and open it again.

  3. Start a conversation tomorrow. Claude begins with a short note on where you stopped, something like this:

    Where you stoppedhandoff.md

    asked Finish the pricing table

    did Pricing table done. The checkout copy is next.

    changed pricing.md

Check it works, and update later

  1. To check it's working, run this. No line should start with PROBLEM. A line that starts with note is fine, such as when Git isn't installed.

    /project-memory:memory doctor

    Until Claude finishes its first reply, one line says it's waiting for that reply. That's normal.

  2. To update later, run these 2 lines in a terminal, then restart Claude Code. A marketplace you add yourself does not update on its own. To turn that on, type /plugin, open Marketplaces, choose project-memory and select Enable auto-update.

    claude plugin marketplace update project-memory
claude plugin update project-memory@project-memory

What you need

  • Claude Code with its built-in memory on. It is, unless you turned it off.
  • Node.js 22 or newer. Choose the LTS version.
  • Git, optional. Without it, everything works except bringing back old versions of notes.
  • Windows, macOS or Linux.

Questions

Questions people ask.

Does it cost anything?

No. It is free and open source under the MIT license, with no account and no API key.

Claude Code can already resume a conversation. Why add this?

/resume reopens one earlier conversation with its whole history, as long as it was when it ended. project-memory starts a fresh conversation with a short briefing on where you stopped, and its journal covers every conversation you don't keep private, not only the one you reopen. Claude Code also deletes its own conversation files after 30 days unless you change that; the journal keeps each exchange until you delete it.

Does it slow Claude down or fill the conversation?

Each conversation starts with a short briefing, about 900 tokens (3,500 characters) on your last conversation, and never more than about 2,400 tokens in all; the note after a summary is usually near that. /project-memory:memory doctor shows how long its steps take on your machine.

How much disk space does it use?

Half of the journal entries are under about 5 KB. A very busy project adds up to about 110 MB a year.

Can I use it on two computers?

Each computer keeps its own notes and journal; they don't sync. Don't sync the memory folder yourself (Dropbox, OneDrive): each computer would undo the other's “forget”.

My model holds 200,000 tokens. Do I need to change anything?

Yes, for long conversations. It assumes a window of 1,000,000 tokens, so the reminder to save notes never comes. Ask Claude: “Is my context window 200,000 tokens?” If it is, ask: “Add CLAUDE_CODE_AUTO_COMPACT_WINDOW set to 200k under env in my Claude Code settings,” then restart Claude Code.

On a bigger model, setting it lower than the model's window (such as 800k on a 1,000,000-token model) also asks Claude Code to let a step finish before it shortens the conversation, and even then it doesn't always wait. The note Claude gets after a summary needs nothing. The details.

How do I stop it saving something?

4 ways, from narrow to wide.

  1. One conversation: /project-memory:incognito stops saving this conversation and removes what it already saved, except the history's copy of days already over. Typing <private-session> does the same. If it says NOT applied, it did not work.
  2. One project: /project-memory:memory-off saves nothing for this project. Search still finds what was saved before. Resume with memory-on.
  3. All projects on this computer: set the environment variable CLAUDE_CODE_DISABLE_AUTO_MEMORY=1, or disable the plugin.
  4. Claude Code itself: Claude Code's own settings. project-memory does not read or change them, so Claude Code's own memory switch does not stop it.

None of these reaches Claude Code's own files. It keeps its own transcript of every conversation, for 30 days unless you change that. Turning it off, in detail.

How do I pause or remove it?

To pause it, run claude plugin disable project-memory@project-memory in a terminal and restart Claude Code. To remove it, type /plugin uninstall project-memory@project-memory in Claude Code. Your notes and the journal stay either way; the privacy policy says what to delete by hand.

Experimental

Checked lessons

A note can carry a rule for git commands. A hook then watches your git calls and logs which note matched. It only watches and logs: it blocks nothing and prints nothing. Few lessons fit this form, and some commands it does not see. It is a 30-day trial, with a keep-or-cut decision on 2026-12-18.

Syntax, limits and how to try a rule on past conversations

enforce:
  on: git add
  has: [-A, --all, .]
  unless: [mktemp, init]

At the top level of a note's front matter (not under metadata:). It logs a hit when a git add command holds -A, --all or a bare dot.

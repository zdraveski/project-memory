# 1.6.0 step 17: run records (plan)

Amended 2026-11-25 after the audit `reports/Audit of 1.6.0 plans 2026-11-25.md` (findings 4, 5, 7, 11, 13).

Spec: `docs/specs/2026-11-24-run-records.md`.

**When:** after step 16. The 1.6.0 order is 15, 16, 17, 18, 3, 4, 5, 6, 7, 8, 9, 11, 12, 14.

**What it is:** one pull request, a pure move. Every existing check passes
with no assertion changes. Only imports change in the tests, plus the file lists
in four tests that copy `src` files (item 8).

**How to work:**
- Branch from `master`.
- Run `node tools/check.mjs` after each edit.
- Sign off every commit.

## Steps

1. Write `test/run-records.test.mjs` first, in-process. For each record, test
   these cases: absent, present, bad JSON, unreadable (make it a directory),
   with a BOM, and with CRLF line ends. Also test the Stop record's cut to 20
   lines past 8 KB. Use today's behaviour as the expected value.
2. **First extract the Stop record into a function, in place.** It is written
   inline in `memory-tier.mjs`'s `main` (`:724-743`, with a touch at `:425`), so
   nothing can move until it is a function. Do this as its own commit, with the
   existing tests as the check.
3. Create `src/run-records.mjs`. It imports Node built-ins and `store.mjs` only.
   It has one read rule:
   - missing is "none";
   - unreadable or unparseable is "damaged";
   - a BOM is stripped.

   It cannot import `journal.mjs`, so it has its own constants for the
   journal folder (`JOURNAL = 'journal'`) and the failure file (`FAILED =
   '.failed'`). `journal.mjs` imports `FAILED` from it (`journal.mjs:448`), and
   one test checks that `JOURNAL` from `journal.mjs` (`:11`) equals the module's
   own, so the two cannot drift.
4. Move these into it, as they are:
   - From `memory-tier.mjs`: `health()` (`:594-601`), and the Stop-record
     function from item 2.
   - From `journal.mjs`: `aside()`, `fault()`, `failures()`, `clear()`
     (`:448-463`).
   - From `handoff-log.mjs`: `edited()` (`:1040`), `hash` (`:1034`, which
     `edited()` needs), `unsaved()` (`:913`), and the record reads in the
     startup line (`:921-941`; the `.snapshot-health` read at `:940-945` is
     step 16's).
   - From `memory.mjs`: `stopRuns` (`:818`), `deployedCommit` (`:122`), and
     `plugins()` (`:110`) with the reads it serves: `installed_plugins.json`
     (`:113`, `:115`; also `memory-tier.mjs:644`) and `known_marketplaces.json`
     (`:119`, `:862`). **Decision:** the `known_marketplaces.json` read moves
     too, because `plugins()` serves both files and `json()` goes. `marketplace()`
     stays in `memory.mjs` and calls the module's reader.
   - From `store.mjs`: `HANDOFF_FAILED` and `JOURNAL_FAILED`.
5. Switch every caller to import from `run-records.mjs`:
   - `memory-tier`, `journal`, `handoff-log`, `memory`
   - `tools/deploy.mjs`, which also writes the deploy record through it, and
     which imports `hash` from here instead of from `handoff-log` (`:17`)
   - the tests and `tools/fuzz.mjs`

   Leave no re-exports behind.
6. Delete `json()` and `read()` from `memory.mjs`, together with the inline
   read copies for these files.
   - Check that every other use of `json()` and `read()` (for example
     `settings.json` at `:882`) moves to the module's reader.
   - Alternatively, those uses keep a reader that is named for its job. Say
     which in the PR.
7. Keep each screen word for word what it is today: doctor, status, the
   startup line and the tier hook. A "damaged" record is shown exactly as that
   screen shows the file today. After 1.5.8's fix (d), that means doctor shows
   a damaged deploy record as a PROBLEM.
8. Update the tools. Since PR #239 they derive their file lists from `src/`, so
   add only a `suites` entry for `run-records.mjs` in `tools/mutate.mjs`
   (`tools/check.mjs` fails without it), its import, and
   `tools/mutants/run-records.mjs`. Repoint the hand mutants whose file changed.
   `tools/deploy.mjs` now imports `hash` from the module, so decide whether it
   joins `SHARED` (`tools/deploy.mjs:23`), together with steps 15 and 16.
9. Fix the tests that copy `src` files into temp trees: add `run-records.mjs` to
   `test/memory-tier.test.mjs:632` and `:1557` and
   `test/handoff-log.test.mjs:565` and `:3062`.
10. Update `docs/how-it-works.md` with the module list.

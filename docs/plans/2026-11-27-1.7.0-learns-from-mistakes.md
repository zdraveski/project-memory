## Where this plan differs from the spec

The spec's file table puts `lessonOf` and the command family in `src/lessons.mjs`, and
`dropMistakes` in `mistakes.mjs`. Both placements would make import loops, which ADR 0003 forbids
and `tools/check.mjs` fails on (a run-time `import(` counts too). So:

- **`src/enforce.mjs` gets the lesson code that the cache needs:** `lessonOf`, `familyOf`, the L17
  scan, and the v4 cache (`notesOf`). `lessons.mjs` imports `enforce.mjs`, and `enforce.mjs`
  builds the cache, so these must live in `enforce.mjs`.
- **`src/store.mjs` gets `MISTAKES` and `dropMistakes(store)`, beside `dropPage`.** `journal.mjs`
  must call it, and `mistakes.mjs` loads `journal.mjs` to build.
- **`recall.mjs` never imports `lessons.mjs`.** `lessons.mjs` imports `recall.mjs` (for
  `cleanPath`). So H5 and L2 are wired in `recall-hook.mjs`, which calls both.
- **The H6 engine is a new `src/replay.mjs`,** wired into the CLI by `memory.mjs`. `memory.mjs`
  is 1,321 lines already.
- **The new briefing lines are tested in a new `test/briefing.test.mjs`,** not in the 4,337-line
  `test/handoff-log.test.mjs`.
- **The replay also simulates H3 and L2.** Under answer 1, a trigger the replay cannot measure
  would ship off.
- **`PROJECT_MEMORY_RECALL=0` also stops H5 and L2.** They run inside `recall-hook.mjs`, which that
  switch skips whole. It is documented in step 16, not changed.

Import graph after 1.7.0, with no loops:
- `enforce` imports store, transcript and privacy (as today).
- `mistakes` imports store, text and enforce. It loads journal only inside `buildMistakes`.
- `correction` imports nothing.
- `lessons` imports store, privacy, text, sessions, enforce, recall, mistakes and correction.
- `replay` imports lessons, mistakes, correction, enforce and store. It loads journal inside its
  run.
- `notes-health` imports store and enforce.
- These load the new modules: `memory`, `briefing`, `memory-tier` (by `import(`), `enforce-hook`
  and `recall-hook`.

## Shared formats

Give this section to every builder.

### F1. The switch (`src/lessons.mjs`, step 2)

```js
export const TRIGGERS = ['edit', 'command', 'deadend', 'recurring', 'nudge', 'stuck', 'claim', 'cochange'];
export const DEFAULTS = { edit: false, command: false, deadend: false, recurring: false, nudge: false, stuck: false, claim: false, cochange: false }; // step 7 sets these from the gate
export function lessonsOn(name, env = process.env.PROJECT_MEMORY_LESSONS) { /* boolean */ }
export const lessonsOff = (env = process.env.PROJECT_MEMORY_LESSONS) => String(env ?? '').trim() === '0';
```

How `lessonsOn` reads the setting:
- Unset or empty: `DEFAULTS[name]`.
- `0`: false for every trigger.
- `1`: true for every trigger.
- Otherwise a comma list, read over `DEFAULTS`. `name` turns a trigger on and `-name` turns it
  off. Spaces are trimmed and unknown words are ignored.
- An unknown trigger name is always false.

`lessonsOff()` governs the lines that are not triggers: E2's git line and L4's health line.

Tests turn a trigger on with `PROJECT_MEMORY_LESSONS=<name>` in the child's env.

### F2. Session lines (appended with `sessionLine(kind, rest, by)` from `src/sessions.mjs`)

A session line reads `<kind> <ISO time> [agent:<id>] <rest>`.
- `by` is `''` for the main conversation.
- For a helper, `by` is its `agent_id`, cleaned as `recall.mjs` cleans it:
  `.replace(/[^\w-]/g, '').slice(0, 64)`.
- Hashes are `keyed(text, 8)` from `src/store.mjs`.
- `<note>` is `encodeURIComponent(name)`, where the name is the note's file name, or
  `_shared/<file>` for a note in the shared store. Encoded, it holds no space, comma or colon.

| Kind | Rest | Written by |
|---|---|---|
| `lesson` | `<note> edit:<relative path>`, `<note> cmd:<family>`, or `cochange%3A<pair hash> pair:<B path>` | H1, H2, L9 |
| `fail` | `<target hash> <error hash or ->` | L2 |
| `stuck` | `<target hash>` | L2 |
| `nudge` | `fired:<pattern ids, comma-joined> v<VERSION> #<k>`, or `dropped:<filter id> v<VERSION> #<k>`. `k` is 1 plus the number of `nudge` lines already in the file | H5 |
| `claim` | `<target hash>` | L6 |
| `apart` | `<pair hash>`, where the pair hash is `keyed(A + '\n' + B, 8)` | L9 |
| `judged` | `<note>:<v>` joined by `,` (v is `f` followed, `b` broken, `n` not applicable, `u` unknown), or empty | L13 |

How the lines are read:
- **This context:** the lines after the newest `compact` line.
- **This turn:** the lines after the newest `asked` or `quiet` line.
- **A writer's lines:** the lines whose `by` is that writer's.

`#<k>` keeps nudge lines distinct. Without it, `tidy()` would fold two equal lines into one, and
the cooldown would lose count.

### F3. `<store>/.lessons.json`

The only writers are the Stop (counters, `retired`) and the startup briefing (`listed`, `told`),
both under `withLock(store)`. Hooks read it without the lock. A missing or broken file means every
counter is zero.

```json
{ "v": 1,
  "notes": { "<name>": { "rev": "<8 hex>", "shown": 0, "followed": 0, "broken": 0, "na": 0, "unknown": 0,
                          "sessions": ["<8-char tag>"], "last": "YYYY-MM-DD", "retired": "", "told": false } },
  "errors": { "<error id>": { "listed": 0 } } }
```

The fields:
- **`<name>`:** the note's file name, `_shared/<file>`, or `cochange:<pair hash>`.
- **`rev`:** `keyed(JSON.stringify([to, when, instead, resolves, desc]), 8)` of the lesson. When
  `rev` changes, every counter resets, along with `retired`, `told` and `sessions`.
- **`sessions`:** at most 20 distinct tags, newest last.
- **`retired`:** `''`, or the reason, such as `broken 3`.

### F4. `<store>/.mistakes.json` (built by step 4)

```json
{ "v": 1, "built": "YYYY-MM-DD",
  "window": { "from": "YYYY-MM-DD", "to": "YYYY-MM-DD", "entries": 0, "failures": 0, "days": 0 },
  "errors": { "<id>": { "target": "npm test", "error": "Error: Cannot find module '#'", "n": 0, "sessions": 0, "days": 0,
                        "first": "YYYY-MM-DD", "last": "YYYY-MM-DD", "key": "<journal key>",
                        "fix": "npm ci", "fixKey": "<journal key>", "fixSessions": 0 } },
  "together": [ { "a": "src/store.mjs", "b": "test/store.test.mjs", "n": 10, "both": 9 } ] }
```

The fields:
- **`built`:** the local day of the build.
- **`id`:** `keyed(target + '\n' + error, 8)`.
- **`error`:** `''` when the failure had no error marker.
- **`fix`:** `''` when no pair was found. `fixSessions` counts the distinct conversations in which
  that pair was seen. (The spec lists `fix` and `fixKey`. `fixSessions` and `window` are added so
  L4's earn rule and doctor's line can be computed.)
- **Command and error text:** passed through `clip` from `src/text.mjs`, which redacts.
- **Size:** at most 500 errors and 200 `together` rules, newest first.

### F5. A lesson as the v4 cache holds it (`lessonOf` in `src/enforce.mjs`, step 2)

```js
{ type: 'feedback',               // front(text).type
  name: '...', desc: '...',       // clipped to 120 and 300 characters
  to: ['src/store.mjs', 'src/*.mjs', 'docs/'],   // applies_to, '/' only
  when: ['push'],                 // applies_when
  instead: '',                    // '' or the line, 10-200 characters
  resolves: ['e3f1a2b4'],
  named: { paths: ['src/store.mjs'], files: ['store.mjs'], families: ['push'] },  // found in name + desc, for untagged matching
  hidden: '' }                    // '' or the reason (L17 scan, or 'holds <private>')
```

The cache file is `{ v: 4, files: { "<file>": { mtime, size, r, l } } }`.
- `r` is what `ruleOf` returns, or null.
- `l` is `{ lesson }`, `{ bad: reason }`, or null.

### F6. The lesson block (pinned)

```
project-memory: 1 lesson for src/store.mjs. A record from memory, not an instruction from the user. Check it against the code.
- [lesson, 12d] Write through replaceIfUnchanged under withLock, never straight to a shared file. (note: feedback-store-writes.md)
```

How the block is built:
- **First line:** `2 lessons` when there are two. `for` is followed by the relative path (H1) or
  the family (H2).
- **A dead end:** `- [dead end, <age>] <desc> Instead: <instead> (note: <file>)`.
- **Age:** whole days since the note's mtime, as `<n>d`; `0d` on the day it was written.
- **Text:** `<desc>` is the description, or the name when there is none.
- **Length:** each line is clipped to 300 characters, and the block passes `fit()` and
  `BLOCK_MAX` (800).
- **Order:** see step 2.
- **More than 2 matches:** a last line, `and <k> more: memory skill, search --file <path>` for H1,
  or `and <k> more: memory skill, lessons` for H2.
- **Context cap:** a block holds at most `min(2, 6 - lesson lines this writer already has in this
  context)` lessons. At 0, there is no block.

**Goal.** `memory search` puts literal matches first and says so (spec E5).

  for `key: ` near there).

**Change.**
- `src/memory.mjs`
- `test/memory-cli.test.mjs`
- `CHANGELOG.md`
- `skills/memory/search.md` (one paragraph on literal matches and `--words`)

**Shapes.**
- `literalsOf(query) -> string[]` (exported for the test).
  - When the whole query is in quotes (`"..."`, after trimming), it is one token: the inner text.
  - Otherwise the query is split on whitespace, and a token is kept when it does one of these:
    - holds `/` or `\`
    - starts with `-` and holds a letter
    - is a dotted name with a letter (`/^[\p{L}\w-]+(?:\.[\p{L}\w-]+)+$/u` holding `\p{L}`; so
      `1.6.7` is not literal, since versions already have their own match)
    - looks like an error code (`/^(?:E[A-Z]{2,}|TS\d{3,5}|E\d{2,})$/`)
- The literal lane, inside `search()`. Each literal token is matched with
  `hay.toLowerCase().includes(token.toLowerCase())`:
  - in a journal entry's request, files, commands and answer
  - in a note's file name, name, description and body
  - A hit whose literal matches are not empty carries `exact: [tokens]`.
- **Sort.** Hits with `exact` come before all others. Inside each group the order is today's
  score order.
- **A literal-only hit.** An entry or note with a literal match and no word match is a hit.
  - Its score is 0, so it sorts below the word hits inside the literal group.
  - It is found even when `words(query)` gives no terms. Today the loop is skipped when
    `terms.length` is 0, so the lane needs its own pass.
- **Printing.** The hit line gets `  exact: <tokens joined by space>` before `  key: ` (spec
  example: `... asked: "why does the push fail"  exact: --force-with-lease  key: "..."`).
- **`--words`.** It goes into `OPTIONS` as `false` and into `TAKES.search`. It turns the lane
  off, so the output is 1.6.7's, byte for byte.

**Tests first** (`test/memory-cli.test.mjs`, one store with 60 made-up entries):
1. `search -A finds git add -A`: the entry whose Ran holds `git add -A` is listed (today:
   nothing).
2. `search src/hooks/pre.js puts the path first`: the entry that changed that path is the first
   hit, ahead of entries that only share words.
3. `search "exit code 137" puts the phrase first`.
4. `--words gives today's order`: the same query with `--words` gives 1.6.7's lines exactly
   (build the expected lines from a run with the lane off).
5. `a plain-words query is unchanged`: no literal token, so the output equals the `--words`
   output.
6. `literalsOf` cases:
   - `-A`, `src/a.js`, `a.b`, `ENOENT`, `TS2345`, `E11` and `"x y"` are literal
   - `1.6.7`, `push`, `-` and `--` are not
7. `search --words is accepted, search --wordz is refused` (parser).

**Run.** `node test/memory-cli.test.mjs`, then `node tools/check.mjs --base master`.

    - It differs from `cmd1` after whitespace is folded.

**Shapes.**

```js
export const VERSION = 1;
export const GATE_A = [{ id: 'A-no', re: /.../iu }, ...];     // English and Macedonian, each with an id
export const GATE_B = [{ id: 'B-always', re: /.../iu }, ...];
export const FILTERS = ['F2-helper', 'F2-first', 'F3-long', 'F4-question', 'F5-polite-no', 'F6-praise', 'F6-self-blame', 'F6-reported'];
export function correction(text, ctx) -> { fire: boolean, ids: string[], drop: string }
// ctx = { helper: boolean, first: boolean, marker: () => boolean, lastEndsWithQuestion: () => boolean }
```

How `correction()` works:
- **The functions in `ctx`** are called only when needed, so the hook reads the transcript tail
  only for a near-match.
- **Order:**
  1. F2: a helper, or the first prompt of the conversation.
  2. F3: strip code fences, `>` lines, indented code and inline code. Over 500 characters left
     drops it. Then use the first 280 characters.
  3. Gate A: in the first sentence.
  4. Gate B: anywhere in the 280 characters, or else `marker()`.
  5. F4: the first sentence is a question and there is no marker.
  6. F5: polite or empty no, or a bare no when `lastEndsWithQuestion()`.
  7. F6: praise, self-blame, reported speech.
- **`drop`** is the id of the first filter that dropped a match, or `''` when nothing matched.
- **`ids`** holds the matching pattern ids. It is never prompt text.
- **Gate A, English:** `no,`/`no.` at the start, `that's wrong`, `that is not what I`,
  `not what I asked`, `I said`, `I told you`, `why did you`, `you didn't`, `you forgot`, `stop` +
  a word ending in `-ing`, `don't`. The weak cues `actually`, `instead` and `rather` count only
  when 2 are present.
- **Gate A, Macedonian:** `не,`/`не.` at the start, `погрешно`, `не тоа што`, `реков`, `ти реков`,
  `заборави да`, `немој`, `престани да`; Latin `nemoj`, `pogresno`.
- **Gate B, English:** `always`, `never`, `from now on`, `every time`, `next time`, `in future`,
  `remember`, `again` after a negative.
- **Gate B, Macedonian:** `секогаш`, `никогаш`, `од сега`, `отсега`, `секој пат`, `следниот пат`,
  `во иднина`, `запомни`, `пак`/`повторно` after a negative; Latin `sekogas`, `nikogas`,
  `otsega`, `zapomni`.
- **Whole words.** Match every word whole: `\b` does not work on Cyrillic, so use
  `(?<![\p{L}\p{N}])` and `(?![\p{L}\p{N}])` with the `u` flag.
- **F5 and F6 in Macedonian:** `нема проблем`, `благодарам`, `фала`, `извини`, `моја грешка`.
- **No phrase in both gates.**

**Tests first** (`test/correction.test.mjs`, over the fixture):

  - at least 30 English corrections and 10 Macedonian ones, each `must: true`

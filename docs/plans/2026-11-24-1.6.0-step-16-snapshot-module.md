   stand-in and covers:
   - how errors map: ENOENT is off, ETIMEDOUT is in parts, each lock message
     is busy, anything else is failed;
   - a damaged index is rebuilt once;
   - the health counts after failure and after success;
   - held and missed;
   - a missing health file and a broken one.

   Use today's outputs as the expected values.
2. Create `src/snapshot.mjs` with one seam for running git. Real git is the
   default, and a test passes its stand-in. Move in, as they are:
   - From `memory-tier.mjs`: `snapshot()`, `snapshotHealth()`, `owed()`,
     `gitignore()`, the `held` and `missed` lists (`:390-391`), and the lock
     sweep (`:430-441`).
   - From `store.mjs`: `gitArgs`, `gitWhy` and `LOCAL_GIT_ENV`.

   It imports only Node built-ins and `store.mjs`.

   **The seam also carries what `main` sets today** (`memory-tier.mjs:672-673`),
   because `snapshot()` depends on it:
   - the git timeout (`GIT_TIMEOUT`, `:33`, 30 s; `main` sets `gitWait` from
     `--git-timeout`) and the batch size (`BATCH`, `:34`; `main` sets `batch`
     from `--batch`), both passed in;
   - the stale-lock age (`GIT_LOCK_STALE`, `:32`);
   - an exported `reset()` that empties `held` and `missed`, which `main` calls
     at `:673` before each run.
3. Switch `memory-tier.mjs` to call it. Keep the background spawn and its order

4. Switch `memory.mjs`, the tests and the tools that import `gitArgs` or

   These change their import:
   - `test/store.test.mjs:14`, `:150`, `:488-495`, `:662-681` and `:937`
   - `test/memory-doctor.test.mjs:1165`

## PR B: the git half of the CLI and the health readers move in

1. Extend `test/snapshot.test.mjs` with the history and restore decisions the
   stand-in can drive. Leave out the history rewrite, which keeps real git.
2. Move in the git half of these `memory.mjs` features, keeping their timeouts
   (60 s, and 300 s for `FAST`):
   - history: `ever`, `unsnapped`, the log reads;
   - restore: `hash-object` and `update-ref`;
   - purge and `rewrite`;
   - rescan: `fast-export`, the bundle, `for-each-ref` and `update-ref`;

3. Move `MISSED` and `HELD` (`:572-574`) out of `handoff-log.mjs`, along with
   its read of `.snapshot-health` (`:940-945`). Every reader then gets the one
   parsed shape, plus whether the file could be read. Each display stays word
   for word what it is today.
4. All existing suites pass with no assertion changes.

## PR C: one busy rule, and the plugin runs git's clean-up (this changes behaviour)

1. Write the failing tests first.
   - In-process, with the stand-in: the busy rule over each lock file, `gc.pid`,
     and stale versus fresh; restore, purge and rescan each refuse while the
     repo is busy.
   - End to end, with real git: a purge while `gc.pid` is present reports busy
     and does not crash.
2. Write the one busy rule in `snapshot.mjs`, and use it before every git write:
   the snapshot, purge, rescan and restore.
   - The snapshot keeps the 10-minute stale rule.
   - Purge keeps holding `config.lock` for its whole run.
3. Add `-c gc.auto=0` to `gitArgs`.
4. After a snapshot that committed, run `gc --auto --no-detach` with
   `-c gc.auto=6700` (git's default) after the `gc.auto=0` that item 3 adds, so
   it wins. Without it, `gc.auto=0` makes `gc --auto` do nothing (checked
   locally).
5. Read the tidy timing line in `doctor` before and after on a large projects
   root, and put both numbers in the PR.
6. Docs: if `PRIVACY.md` or the README describe what restore does, add the new
   "busy" refusal there. Add a CHANGELOG line worded for people, for example:
   "Restore now waits for a snapshot in progress instead of racing it."
7. In its own commit, drop #230's `gc` retry (`memory.mjs:515-517`, inside
   `rewrite()`), but only after a mutant run on those lines shows nothing else
   needs it. No hand mutant covers those lines, so the run is the automatic
   mutants only (`--auto-lines`). If the run says otherwise, keep the retry and
   say why in the PR.

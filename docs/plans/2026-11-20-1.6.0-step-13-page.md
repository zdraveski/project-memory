# 1.6.0 Step 13: A Page You Can Open (release 1.5.4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `memory page` writes one local HTML file that shows the journal of every project, a week at a time, and prints its `file://` link.

**Architecture:** `memory.mjs` gets a `page` command that reads the journal the way `search` does and hands plain data to a new file, `page.mjs`. `page.mjs` is pure: it turns that data into one HTML string with one style block, one script block and a Content-Security-Policy that allows only those two by hash. The commands and hooks that remove journal text delete the file.

**Tech Stack:** Node.js 22+ ES modules, `node:crypto` for the hashes, `node:assert`. No dependency. The page itself is plain HTML, CSS and one script, with nothing loaded from anywhere.

**Spec:** `docs/specs/2026-11-19-1.6.0-design.md`, sections "Headline 3: A page you can open", "Build order" (the paragraph "Order changed on 2026-11-20" and step 13), "Testing". Part of release 1.5.4. Built on the branch of `2026-11-20-1.6.0-step-10-who-said-it.md`.

**The look:** `docs/plans/page-look/reference.html` is a working mock-up of the page with made-up entries, and `reference.png` is how it renders at 1440 x 900. The maintainer picked look 3 ("Week first") from four rendered variants on 2026-11-20 and asked for this bolder form. Their yes to this exact form must be in the pull request before Task 4 is built. Open the file in a browser before reading Task 4.

## Global Constraints

- Node 22 or newer, no dependencies, no network. Windows, macOS and Linux.
- The file is `<config dir>/project-memory/journal.html`. Folder mode `0o700`, file mode `0o600`. Never inside a project folder.
- The data sits in the page as JSON with every `<` escaped. The script sets text with `textContent` (or `append` of strings and nodes it made) only. Never `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write`, `eval`, `new Function`, or `setAttribute('style', …)`.
- One `<style>` block and one `<script>` block. A `Content-Security-Policy` meta tag before both: `default-src 'none'; img-src data:; style-src 'sha256-…'; script-src 'sha256-…'`. `img-src data:` is there for the one logo picture, which sits inside the file; it lets nothing in from the network. No `style` attribute in the markup, also not inside the SVG. The script may set styles through `element.style` and `classList`: the policy allows that.
- Nothing the page fetches: no `<link>`, `<iframe>`, `url(`, `@import` or `fetch`; one `src=`, the logo's `data:` picture; one `href=`, the skip link `href="#list"`. System fonts, Inter when installed. Every icon is inline SVG.
- **The logo is the project page's.** `docs/art/brain.png` (148 x 136 px, 14,221 bytes) as base64 in a constant of `page.mjs`, in the page's one `<img>`, with the ring, its moon and the recall trace as `docs/plans/page-look/reference.html` has them. The builder reads no picture file when it runs. The three start delays of the trace are classes, because the page allows no `style` attribute.
- Every string from the journal passes `redact` (`store.mjs:865`) when the page is built.
- Forgotten entries, entries of switched-off projects and the text of private turns never reach the file.
- Test fixtures are made up. Nothing from a real conversation goes into the repo, a commit message, a picture or a pull request.
- Test first. `node check.mjs` green before every commit. One change a commit. Stage files by name, never `git add -A`.
- Every commit is signed off (`git commit -s`) and its message ends with the session's `Co-Authored-By` line. Write commit messages and scripts to files, not heredocs.
- Line numbers are those of master at 8bf5f95, before steps 1, 2 and 10 are built: confirm each before editing.
- No mutant or fuzz run on GitHub's machines unless the maintainer says "run". No merge without the maintainer's "merge". This pull request is stacked on `1.5.4-who-said-it`: retarget it to `master` before that one merges with `--delete-branch`.

## Decisions this plan makes (beyond the spec)

- **Two files.** `page.mjs` builds the HTML from data and touches no disk. `memory.mjs` reads, filters, writes and prints. The split lets every safety rule be tested without a store on disk.
- **The data, exact.** `{ built: 'YYYY-MM-DD HH:MM', today: 'YYYY-MM-DD', days: number | 'all', entries: [{ d, t, c, b, p, q, a, f, n, priv, cut }] }`, entries newest first. `d` day, `t` time `HH:MM`, `c` the conversation tag (`e.s`), `b` branch, `p` the project's name, `q` asked, `a` answered, `f` the changed paths, `n` 1 when it wrote a note, `priv` 1 for a private turn, `cut` 1 when `a` was cut. The project list and every count are worked out in the page from `entries`.
- **It goes in the one script block** as its first statement, `const DATA=<json>;`, with `<` written as `<`. The hashes are worked out last, over the exact text between the tags.
- **Sizes.** `q` is cut to 2,000 characters and `a` to 4,000 with `clip` (`handoff-log.mjs:439`). The page shows two lines of an answer and "Show more" opens what the page holds. When `cut` is set the open card ends with "Cut here. The journal holds the rest: memory show". The spec says "cut short and expandable", and this keeps 30 busy days under about 10 MB.
- **A private turn shows nothing of itself.** An entry whose `answered` is `[private]` goes into the data with `priv: 1` and empty `q`, `a`, `f` and `b`, and the page prints "Private exchange. Its text was not kept." The journal can still hold the request of such a turn (`journal.mjs:71-88`): the page is stricter, because the file leaves the store. Read those lines first and confirm that `answered === '[private]'` is the mark for every private turn. The spec says such a turn is "shown as `[private]`"; the page's sentence differs, so list it in the pull request under the decisions beyond the spec.
- **Helpers' entries are left out** (`key.startsWith('subagent-')`) and counted in the command's "left out" line. They are a helper's work log, not what the user asked.
- **A switched-off project is skipped by this command.** `search` does not skip one, so call `isOff(dir)` (`store.mjs:219`) on every store.
- **"Wrote a note"**: a changed path that, cleaned as `recall.mjs` cleans a path, lies under a store's folder, ends in `.md`, and is neither `handoff.md` nor under `journal/`.
- **A project's name** is what `project(d)` gives (`memory.mjs:1153`). Two stores with one name get the store folder's name added in brackets, so they stay apart.
- **`--days`** takes a whole number from 1 up, or `all`. Default 30. Anything else prints `--days takes a number of days or all, not <value>` and exits 1, in the form of the `--limit` message (`memory.mjs:1113`). The days are counted back from today, today included, by the PC's clock (`local`, `store.mjs:340`).
- **`--project`** matches a project's name or its store folder's name, case ignored. A miss prints `no project named <value>. Projects with a journal: <names, comma separated>` and exits 1.
- **Nothing to show** prints `nothing to show: no journal entry in the last <N> days` (or `in any project` for `all`), exits 1 and writes no file. A page already there stays.
- **A stale page says so.** The page compares `DATA.today` with the browser's date. On another day it shows a bar on top, "Built N days ago. Run memory page for today.", and the labels "Today" and "Last 7 days" become dates.
- **The 30-day strip** shows the last `min(days, 30)` days. The week buttons go back to the oldest day in the data.
- **A search shows 100 matches**, then a "Show 100 more" button. A day shows all its entries.
- **Deleted in more places than the spec names.** The spec names `forget`, `incognito`, `off` and `rescan --apply`. The hooks remove journal text too (`drop` `journal.mjs:296`, `sweep` `:319`, `takeBack` `:488`). A page that still held that text would defeat them, so each one deletes the page when it removed something. The deletion is one `rmSync(path, { force: true })` in a `try`, and never fails a hook.
- **Left out, named in the pull request:** an `--open` flag, the entry's key on the card, a light theme, and a page that refreshes itself.
